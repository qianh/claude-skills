# 周报生成

接收用户的碎片化工作笔记，整理成口语化风格的 Markdown 周报。

## 输入处理

接受任何格式的输入：流水账、要点列表、对话截图描述、随手记录等。

**若用户未提供内容**（只说"帮我写周报"），先问一个问题：
> 本周主要做了哪些事？简单说几个关键点就行。

**若「本周工作」内容明显不足**（少于2个事项），同样先询问补充，再生成报告。

## 四个板块规则

| 板块 | 必要性 | 处理方式 |
|------|--------|---------|
| 本周工作 | 必须有 | 从输入提取，适当润色 |
| 下周计划 | 建议有 | 未提供时根据本周内容合理推断，末尾加`（推断，请确认）` |
| 想法&意见 | 可选 | 无内容则省略整个板块 |
| 需要的帮助 | 可选 | 无内容则省略整个板块 |

## 语言风格

目标：口语化、接地气，有点个人语气，不要像官方公文。

**好的表达：**
- "修了登录的 bug，用户反馈少多了"
- "跟设计对齐了新版 UI，大体没问题了"
- "这周主要在推进 xxx，进展还算顺"
- "遇到了个坑，xxx 的方案还没定下来"
- "下周打算继续搞 xxx，争取搞定"

**避免的表达：**
- "本周成功完成了……的工作"
- "下一阶段计划全力推进以下任务"
- "经综合分析，建议……"
- "高效推进"、"圆满完成"等套话

## 输出格式

```markdown
## 本周工作
- xxx
- xxx

## 下周计划
- xxx
- xxx

## 想法&意见
- xxx

## 需要的帮助
- xxx
```

**注意：**
- 无内容的可选板块直接省略，不要留空板块
- 每个要点简洁，通常1-2句话
- 技术术语保留英文（如 bug、PR、API）

## 示例

**用户输入：**
```
帮我写周报
本周：修了登录bug，开了3次需求评审，跟设计对齐了新版UI
下周想做用户中心改版
有个问题：新功能上线需要后端同学配合，目前排期还没确定
```

**生成结果：**
```markdown
## 本周工作
- 修了登录 bug，现在稳多了，用户侧反馈也少了
- 参加了 3 次需求评审，主要在推进新功能的方案确认
- 跟设计过了一遍新版 UI，大体对齐了

## 下周计划
- 启动用户中心改版，先把交互方案理清楚
- 跟进新功能上线的排期问题

## 需要的帮助
- 新功能上线需要后端同学配合，但排期还没定——希望能尽快确认一下时间节点
```
